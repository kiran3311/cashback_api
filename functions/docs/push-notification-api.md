# Push Notification API Guide

This guide documents the Firebase Cloud Messaging (FCM) APIs and the cashback operations that trigger push notifications.

## Base URL

Local development:

```text
http://localhost:5001
```

Replace the base URL with the deployed API address in production.

## Common request headers

All endpoints use JSON.

```http
Content-Type: application/json
```

The current routes do not require an authorization header.

## How notifications work

1. The Android app obtains an FCM token from Firebase.
2. The app sends the token and logged-in user's Firestore document ID to `POST /save-fcm-token`.
3. The API stores the token in Firestore at `users/{userId}`.
4. A cashback/redeem operation or `POST /send-push-notification` calls Firebase Admin.
5. Firebase delivers the notification to the device that owns the token.

> Never put a Firebase Admin service-account key in an Android app or browser frontend. It belongs only on the server.

## 1. Save FCM token

Saves the latest FCM token and adds it to the user's saved device tokens.

**Endpoint**

```http
POST /save-fcm-token
```

**Request body**

```json
{
  "userId": "XnCC21I6fP9CSx7vN5qw",
  "fcmToken": "REAL_FCM_TOKEN_FROM_ANDROID"
}
```

| Field | Required | Description |
| --- | --- | --- |
| `userId` | Yes | Firestore document ID from the `users` collection. |
| `fcmToken` | Yes | FCM registration token generated by the Android app. |

**Success response — 200**

```json
{
  "success": true,
  "message": "FCM token saved successfully"
}
```

**Validation response — 400**

```json
{
  "success": false,
  "message": "userId and fcmToken are required"
}
```

**Firestore result**

```text
users/{userId}
  fcmToken: "latest-device-token"
  fcmTokens: ["token-from-device-1", "token-from-device-2"]
  fcmTokenUpdatedAt: <date>
```

## 2. Send a push notification manually

Sends a custom notification to all unique FCM tokens saved for one user.

**Endpoint**

```http
POST /send-push-notification
```

**Request body**

```json
{
  "userId": "XnCC21I6fP9CSx7vN5qw",
  "title": "Cashback received",
  "body": "You received Rs. 20 cashback.",
  "data": {
    "type": "CASHBACK_RECEIVED",
    "cashbackId": "cashback_001"
  }
}
```

| Field | Required | Description |
| --- | --- | --- |
| `userId` | Yes | Recipient user document ID. |
| `title` | Yes | Notification title shown to the user. |
| `body` | Yes | Notification body shown to the user. |
| `data` | No | Extra notification data. Values are converted to strings before sending to FCM. |

**Success response — 200**

```json
{
  "success": true,
  "successCount": 1,
  "failureCount": 0
}
```

**No saved token / failed delivery — 400**

```json
{
  "success": false,
  "error": "No FCM token found for user"
}
```

**Validation response — 400**

```json
{
  "success": false,
  "message": "userId, title and body are required"
}
```

The API writes a delivery log to the Firestore `notifications` collection.

## 3. Add customer to shop and issue cashback

Creates/updates the customer link, creates a cashback record, then sends a **Cashback received** push notification to the customer.

**Endpoint**

```http
POST /adduserToShop
```

**Request body**

```json
{
  "shopkeeperId": "SHOPKEEPER_FIRESTORE_ID",
  "name": "Rahul Kumar",
  "mobile": "9876543210",
  "customerEmail": "rahul@example.com",
  "billAmount": 500,
  "cashback": 20,
  "issueCashback": true
}
```

**Success response — 200**

```json
{
  "message": "Customer added and cashback updated",
  "userId": "XnCC21I6fP9CSx7vN5qw"
}
```

**Important conditions**

- `shopkeeperId`, `name`, and `mobile` are required.
- The mobile number must exist in the `users` collection.
- The matching user must have `profile: "customer"`.
- The customer needs a saved FCM token for delivery to succeed.

## 4. Add cashback to an existing customer

Creates a cashback record for a customer already linked to the shopkeeper and sends a **Cashback received** push notification.

**Endpoint**

```http
POST /addCashbackToExistingCustomer
```

**Request body**

```json
{
  "shopkeeperId": "SHOPKEEPER_FIRESTORE_ID",
  "mobile": "9876543210",
  "billAmount": 1000,
  "cashback": 50,
  "issueCashback": true
}
```

**Success response — 200**

```json
{
  "message": "Cashback added successfully",
  "cashbackId": "NEW_CASHBACK_DOCUMENT_ID",
  "userId": "XnCC21I6fP9CSx7vN5qw"
}
```

**Common errors**

```json
{ "message": "shopkeeperId, mobile, billAmount and cashback are required" }
```

```json
{ "message": "Customer not registered" }
```

```json
{ "message": "Customer not linked to this shopkeeper" }
```

## 5. Request cashback redemption

Creates a redeem-request notification through an external notification service. This route does not call the local Firebase notification service directly.

**Endpoint**

```http
POST /redeemCashback
```

**Request body**

```json
{
  "customerMobile": "9876543210",
  "cashbackId": "CASHBACK_DOCUMENT_ID",
  "redeemAmount": 50
}
```

**Success response — 200**

```json
{
  "message": "Cashback redeem request notification send successfully",
  "cashbackId": "CASHBACK_DOCUMENT_ID"
}
```

The current implementation posts this payload to the external service:

```json
{
  "userId": "CUSTOMER_FIRESTORE_ID",
  "notificationId": "CASHBACK_DOCUMENT_ID",
  "redeemAmount": 50,
  "message": "Shopkeeper wants to redeem ₹50. Approve?"
}
```

## 6. Approve or reject cashback redemption

Updates the cashback record and sends an FCM notification about the result.

**Endpoint**

```http
POST /updateRedeemStatus
```

**Approve request**

```json
{
  "cashbackId": "CASHBACK_DOCUMENT_ID",
  "action": "APPROVED",
  "redeemAmount": 50
}
```

**Approve response — 200**

```json
{
  "message": "Redeem approved successfully"
}
```

**Reject request**

```json
{
  "cashbackId": "CASHBACK_DOCUMENT_ID",
  "action": "REJECTED",
  "redeemAmount": 50
}
```

**Reject response — 200**

```json
{
  "message": "Redeem rejected successfully"
}
```

**Validation response — 400**

```json
{
  "message": "cashbackId and action are required"
}
```

**Current recipient logic**

| Action | Recipient |
| --- | --- |
| `APPROVED` | Shopkeeper (`cashbackData.shopkeeperId`) |
| `REJECTED` | Customer (`cashbackData.userId`) |

## Automatic FCM trigger summary

| Endpoint | Event | Notification sent |
| --- | --- | --- |
| `/adduserToShop` | Cashback record is created | Customer receives `Cashback received`. |
| `/addCashbackToExistingCustomer` | Cashback record is created | Customer receives `Cashback received`. |
| `/updateRedeemStatus` | Redemption is approved or rejected | A redeem status notification is sent using the recipient rules above. |
| `/send-push-notification` | Manual API call | Custom notification is sent to the requested user. |
